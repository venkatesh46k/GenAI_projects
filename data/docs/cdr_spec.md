# Call Detail Record (CDR) Specification

A Call Detail Record (CDR) is the raw usage record generated by the network every time a subscriber makes a voice call, sends an SMS, or uses mobile data. CDRs are the input to the rating engine, which turns usage into a monetary charge deducted from the prepaid balance.

## CDR fields

| Field | Description |
|---|---|
| cdr_id | Unique 8-character identifier of the record. |
| msisdn | The 10-digit mobile number of the subscriber that generated the usage. |
| call_type | One of `voice`, `sms` or `data`. |
| duration_sec | Length of a voice call in seconds. Empty or not meaningful for SMS and data records. |
| data_mb | Volume of data consumed in megabytes. Only meaningful for `data` records. |
| charge | The amount deducted from the balance, in rupees. It is 0 when usage is covered by the active plan's bundled allowance. |
| timestamp | ISO-8601 date and time at which the usage started. |

## How charge is calculated

The rating engine applies the following logic for each record:

1. Identify the subscriber's active plan at the record timestamp.
2. Check the remaining bundled allowance for that call type (voice minutes, daily data, daily SMS).
3. Usage that fits inside the allowance is rated at zero charge.
4. Usage beyond the allowance is rated at the out-of-bundle tariff and the resulting amount is stored in `charge`.

Voice is rated per started minute for out-of-bundle usage, so a 61-second call counts as 2 minutes. Data is rated per megabyte and SMS per message. Rounding is applied to two decimal places.

## Common CDR questions

- **Why is my charge 0?** The usage was covered by your plan bundle.
- **Why was I charged during an active plan?** The daily data limit or the SMS limit was exhausted, or the call was to a number type not covered by the bundle.
- **Duplicate CDRs.** If two records share the same timestamp, duration and call type, they may be a duplicate. This is a valid ground for a billing dispute; see the dispute resolution SOP.

Subscribers can review their most recent records through the CDR lookup, which returns the latest records first (default 10).
